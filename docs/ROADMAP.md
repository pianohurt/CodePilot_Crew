# CodePilot_Crew 分阶段实现与个人展示计划

制定于 2026-11-02，更新于 2026-11-03。S0—S8 本机 Windows 验收完成，239 项离线测试通过。实际验证范围见 PROGRESS。

## 目标与范围

参考 KamaClaude 的执行思想及 AemeathCode 的阶段推进方法，使用 AI 辅助完成新的 CodePilot 实现。核心能力按当前简历的四条主线组织：Agent 循环与工具调用、多 Agent 任务编排、上下文压缩与流式重试、MCP 集成与 Skills 扩展。

个人工作体现在需求定义、接口和状态设计、实现集成、故障定位、验收与取舍说明。AI 可以生成代码、测试和文档；对外描述应保留参考来源及 AI 辅助事实，不声称纯手写或未经测量的效果。

技术栈沿用 Python 3.12、asyncio、Pydantic、Anthropic Messages API 兼容接口、Textual、pytest、uv。Windows 原生可运行是本项目的验收要求，同时尽量保持 Linux 兼容。

## 一直遵守的执行约定

- 执行状态与依赖分开：每个 run 拥有自己的消息、步骤和结果；服务对象通过显式依赖注入提供。
- 模型负责提出动作；程序负责参数校验、授权、执行、结果配对与停止条件。
- 保留 session_id、run_id、step、tool_use_id 等关联信息，按阶段逐步接入。
- 运行工作历史可压缩，原始交互记录独立保存；持久化不能依赖被压缩消息列表的旧偏移。
- 工具执行以完整解析的模型响应为准；传输中的半截调用不得产生文件或命令副作用。
- 子 Agent 的工具权限不得扩大父级范围。上下文隔离不等于文件系统隔离。
- 每阶段先有外部可观察的验收条件，再实现。测试覆盖行为与故障边界，避免只重复实现内部逻辑。
- 固定响应模型用于稳定复现，真实模型用于检查实际任务效果，两类结果分开记录。

## S0：工程骨架与通信

具体设计与接口见 [S0_DESIGN.md](S0_DESIGN.md)，实际验收见 [S0_VALIDATION.md](S0_VALIDATION.md)。本机已通过 51 项离线测试、独立安装与 Windows 控制台退出/重启；Linux 和远端 CI 尚未执行，不宣称已通过。

目标：前端能可靠连接后台，项目能在本机安装、启动、停止。

实现：
- 独立包、启动命令、配置模型、依赖锁与日志入口。
- 本地 TCP + NDJSON + JSON-RPC 风格请求/响应；Pydantic 信封和错误结构。
- core、ping、version 命令，以及连接、断开、无效请求处理。
- Windows 兼容的退出机制与资源清理；CI 从最小离线检查开始运行。

验收：命令返回正确版本与 pong；无效 JSON 返回可解释错误；客户端断开不拖垮服务；退出后端口释放，同端口能够再次启动。

阶段产物：最小可安装项目、通信测试、S0 说明与演示记录。

需要能解释：为什么后台与界面分开；一条请求怎样找到对应响应；关闭时需要释放哪些资源。

## S3：受控写入、命令执行与权限

实际状态：0.4.0 已完成本机 Windows 验收，164 项离线测试通过；独立安装后的固定响应 5 步、真实 deepseek-flash 4 步，均实际挂载 TUI 并完成临时示例修复，独立检查从退出 1 变为 0。真实提示不含修复答案；受限自动化点击本次审批。拒绝无副作用、冲突、进程树清理和权限归属已有行为证据。详见 PROGRESS 与本地 S3_VALIDATION/S3_WALKTHROUGH。写入和命令默认 ask，Windows 的 bash 工具实际运行 PowerShell。

目标：助手能够修改和验证代码，执行边界由程序落实。

- 区分参数错误、授权拒绝、超时、执行错误；S3 不自动重试有副作用动作，模型连接/读取重试留在 S5B。

验收：允许后能修改示例文件并运行其测试；拒绝时文件没有变化、命令没有执行；超时和取消后无遗留测试进程；错误结果与调用编号保持配对。

阶段产物：一个完整的“定位示例错误 → 修改 → 运行检查”案例。

需要能解释：权限检查在哪一层；为什么写入失败后不能一律重试；应用层权限能保证到什么程度。

## S4：会话、原始记录与持久信息

实际状态：0.5.0 已完成本机 Windows 验收，195 项离线测试通过，含会话并发、原始记录独立保存、配对检查、笔记/背景、损坏隔离、CLI 和实际挂载 TUI。最终独立安装的固定响应和真实 deepseek-flash 均完成 2 步读取 → 新 Core 1 步追问；原文件已删除，恢复请求含旧观察且零工具调用。直接终止 Core 的固定故障案例也验证 interrupted 和不重放。详见 PROGRESS、本地 S4_VALIDATION/S4_WALKTHROUGH。

目标：连续追问可延续，重启后台后能恢复旧会话继续对话。

实现：
- SessionManager、SessionStore、会话列表、resume、同会话并发控制。
- 工作消息 messages 与本轮原始增量 record 分开；磁盘按 run 保存原始记录并维护索引。
- 会话元信息、任务引用与用量统计；安全写入及损坏记录处理。
- 项目背景文件与显式 note_save。第一版笔记限定会话范围，避免默认跨会话复用过时事实。
- 写入与读回时检查工具消息配对，异常中断留下明确状态。

验收：两轮对话能够引用前轮实际结果；停止并重启服务后能列出并恢复会话；历史配对检查通过；损坏或中断记录得到明确处理。

阶段产物：跨进程恢复演示与存储格式说明。

边界：本阶段保证已保存会话的继续交互，不把恢复旧对话说成任意工具动作的原位续跑；已发生的写操作不盲目重放。

需要能解释：session 与 run 的区别；原始记录、工作消息、笔记分别什么时候写和读。

## S5：上下文压缩与流式异常恢复

这一阶段拆为 S5A、S5B 两个可独立验收的任务，分别提交。

0.6.0 已完成 Windows 验收。S5A 通过真实模型摘要及原始记录对照。S5B 通过离线断流注入、实际终端挂载、单次写入核对，以及独立安装后的真实流式读取。

### S5A：长任务上下文

实现：发送前统一检查请求预算，考虑消息、系统提示、工具定义，并预留输出与余量；先处理过长工具输出，再压缩较早的完整交互，保留最近已配平的轮次。

摘要保留任务目标、约束、完成情况、文件状态、待办与验证状态。辅助摘要调用也有输入预算和失败处理。压缩只修改工作历史，原始记录持续保存。第一版恢复时可由原始记录重建并按需再次压缩；后续是否持久化摘要快照，用实际重复压缩成本决定。

验收：长输出不会在没有检查的情况下直接进入下一次超限请求；连续压缩后仍能继续；约束与验证状态被保留；空摘要、压缩失败和重启恢复均有案例。

### S5B：模型流式重试

实现：针对明确的连接/读取错误有限次退避；每次尝试有独立缓存与日志。控制 SDK 与外层重试的总次数。成功后使用完整响应替换草稿；只在完整响应解析通过后执行工具。

验收：首次无文字即断开、半途断开后成功、所有尝试失败、多 run 交错各有验证；最终界面与实际采用的回答一致；模型传输重试不重复执行写入。

阶段产物：两个故障注入演示与上下文策略说明。

需要能解释：截断、摘要和笔记各自解决什么；为什么重试不能理解为从中断 token 继续生成。

## S6：多 Agent 委派与生命周期

0.7.0 已完成 Windows 验收。前台调查与审查、后台查询和根任务清理均有离线用例。真实模型复验完成临时模块读取和精确标识交接。

目标：主 Agent 能委派子任务，支持前台等待和后台运行，并正确收集结果。

实现顺序：
1. spawn_agent 前台模式：独立上下文、明确交接内容、结构化执行结果。
2. planner/executor/reviewer 的角色提示与工具范围，父级、角色、运行策略求交。
3. 后台任务注册、run_id 返回、agent_result 查询与真实执行状态判断。
4. 父子事件关联、并发数量、委派深度、全树调用/时间预算和用量汇总。
5. 定义正常结束、取消、超时和服务退出时的子任务策略，并等待清理完成。

委派说明包含目标、输入事实、约束、允许动作和验收要求。第一版并发主要用于只读调查，写入集中到明确的执行链路；共享文件系统的边界在文档中说明。

验收：前台结果回填；后台查询能区分运行中、成功、失败与取消；步数耗尽不会伪报成功；父级禁止的工具对子级仍禁止；取消后不遗留任务；父子成本合计正确。

阶段产物：一个模块调查与审查协作案例，以及一个父任务在后台调查期间继续工作的案例。

需要能解释：独立上下文为什么仍需交接约束；前台与后台各适合什么任务；如何判断子任务真正成功。

|---|---|
| 自动压缩后的历史写回 | S4 分开工作副本与原始记录，S5 回归验证 |
| 流式重试后的完整回答覆盖 | S2 建立增量/完成事件，S5B 注入断流验证 |
| MCP isError 保留 | S7 的必测行为 |
| Skill 参数、空白名单及委派限制 | S6 权限继承 + S8 真实请求与工具范围验证 |

旧测试可作为案例规格与对照实现；新的接口与存储格式需要相应重写测试。原有 295 项测试成绩属于当前参考版本，重构分支重新记录结果，不沿用旧数字作为新实现成绩。

## 每个阶段的 AI 协作方式

1. 写阶段说明：目标、范围、接口、状态变化、停止条件和验收案例。
2. 按有限任务生成与集成代码，保留参考文件或设计来源。
3. 运行行为测试与必要演示，检查失败路径和边界；真实模型调用单独标注。
4. 讲解关键调用链，并回答输入从哪里来、谁改变状态、失败如何处理、为什么这样设计。
5. 更新阶段说明、验证记录和已知限制，区分计划、已执行和待验收。
6. 按当次授权完成逻辑提交与阶段标签；阶段结束后由用户指定下一阶段。

每阶段达到“能运行、能解释、能复现、能验收”后进入下一阶段。没有固定每天的提交数量，也不预设效果提升数字。

## 本轮不额外扩大的范围

第一版聚焦简历中的本地编程 Agent。分布式调度、多租户后端、任意步骤事务续跑、完整文件系统隔离等能力不作为阶段完成条件；若后续真实使用暴露需求，再单独规划。
